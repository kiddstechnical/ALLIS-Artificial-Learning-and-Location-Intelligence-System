# 2. Why this registry exists

R3 was created because source reconciliation showed that the current implementation did **not** support treating named Hilbert-domain architecture as already admitted to the ordinary-chat Judge Context Packet.

The current qualified source state showed:

```text
current JCP = exactly four top-level fields
```

and:

```text
current Hilbert/tensor/spatial JCP fields = none
```

and:

```text
H_geo current JCP admission = NO

H_p current JCP admission = NO

H_people current JCP admission = NO
```

At the same time, the evidence supported a qualified static H_geo path.

R3 therefore had to preserve both:

```text
static H_geo qualification exists
```

and:

```text
live H_geo JCP admission does not exist
```

This registry keeps those propositions explicit.
